# Senior UX (Korean, 50~60대)

## 페르소나
- 55~65세, 카카오톡 단톡방(가족·동창·지인)에서 영상을 자주 받고 전달한다
- 스마트폰 기본 사용은 익숙하지만 설정·권한 팝업은 부담스럽다. 자녀가 앱을 설치해주는 경우가 많다
- "AI 슬롭", "딥페이크"라는 말을 모르거나 막연히 안다
- 감동·분노·놀라움을 주는 영상일수록 확인 없이 공유한다
- 목표: **공유 버튼을 누르기 전에 한 번 멈추게 하는 것.** 사용자를 가르치는 게 목표가 아니다

## 확률 표현
숫자만 보여주지 않는다. 신호등 + 한 문장 + (작게) 숫자 순서로 보여준다.

| verdict | 색/아이콘 | 헤드라인 | 보조 문장 |
|---------|----------|---------|----------|
| `likely_ai` | 빨강 ● | AI로 만든 영상일 가능성이 높아요 | 다른 분께 보내기 전에 한 번 더 생각해 주세요 |
| `uncertain` | 노랑 ● | AI로 만들었는지 확실하지 않아요 | 출처가 확실한 곳에서 같은 내용을 찾아보세요 |
| `likely_real` | 초록 ● | AI로 만든 흔적은 찾지 못했어요 | 그래도 내용이 사실인지는 따로 확인이 필요해요 |
| `unknown` | 회색 ● | 이 영상은 확인하지 못했어요 | 잠시 후 다시 시도해 주세요 |

- `likely_real`을 "진짜 영상이에요"로 쓰지 않는다. 탐지 실패를 진짜 보증으로 오해하게 된다.
- 퍼센트는 "AI 가능성 87%" 형태로 작게, 헤드라인 아래에. 색만으로 의미를 전달하지 않는다(색각 이상 대비 아이콘·문장 병행).

## 문구 원칙
- 존댓말 "~해요"체. 명령·훈계("공유하지 마세요!") 대신 제안("한 번 더 생각해 주세요").
- 금지어 → 대체어: AI 슬롭 → AI로 만든 영상 / 딥페이크 → 얼굴을 바꾼 가짜 영상 / C2PA·메타데이터 → 영상에 남은 제작 기록 / 확률 → 가능성 / 분석 → 확인
- 근거 문장(`evidence_ko`)은 한 문장, 25자 안팎, 주어를 구체적으로: "유튜브에 'AI로 만든 콘텐츠' 표시가 있어요"
- 사용자 탓 금지: "속으셨네요", "이런 걸 믿으시면" 류 절대 금지

## 화면 원칙
- 본문 최소 18pt, 헤드라인 24pt 이상. 시스템 글자 크기 확대(Dynamic Type/글꼴 크기)를 따라 커져도 깨지지 않게
- 터치 영역 최소 48×48dp. 주요 버튼은 화면 폭 가득
- 한 화면에 주요 행동 하나. 홈 = [붙여넣기] 큰 버튼 하나 + 입력칸
- 로딩은 "확인하고 있어요… (보통 10초 정도 걸려요)"처럼 예상 시간을 알린다 — 기다림을 고장으로 오해하지 않게
- 결과 화면 하단: [가족에게 결과 보내기(카카오톡)] [다른 영상 확인하기]

## 에러 문구 (contract 에러 코드 매핑)
| code | 문구 |
|------|------|
| `invalid_url` | 영상 주소가 아닌 것 같아요. 유튜브에서 '공유 → 링크 복사'를 눌러 다시 붙여넣어 주세요 |
| `unsupported_platform` | 아직 이 사이트의 영상은 확인할 수 없어요. 지금은 유튜브 쇼츠를 확인할 수 있어요 |
| `video_unavailable` | 영상을 열 수 없어요. 삭제되었거나 비공개 영상일 수 있어요 |
| `file_too_large` | 영상이 너무 커요. 1분 이내 영상을 넣어 주세요 |
| `rate_limited` | 잠시 후 다시 시도해 주세요 |
| `detectors_down` / 네트워크 | 지금은 확인이 어려워요. 잠시 후 다시 시도해 주세요 |

지원 플랫폼이 늘면 `unsupported_platform` 문구를 함께 갱신한다.

## 산출물 형식 (`_workspace/02_ux_spec.md`)
1. 가정(요구사항이 불명확했던 부분)
2. 화면 목록과 흐름 (텍스트 와이어)
3. 화면별 문구 표 (키 → 문구) — 앱의 `ux/copy.ts` 키와 1:1
4. verdict 표현 표, 에러 문구 표
